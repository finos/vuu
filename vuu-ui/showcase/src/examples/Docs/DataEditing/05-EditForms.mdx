# Edit Forms

There are three form components, from most to least complete:

| Component | Use it to |
| --------- | --------- |
| `TableWithEditForm` (`@vuu-ui/vuu-table-extras`) | show a table with a form for the selected row in a side panel, with Edit and New. To arrange the pieces yourself, compose the [`TableEditor` components](#composing-your-own-layout) it is built from |
| `CreateRowForm` | add a row from a list of fields |
| `EditForm` | lay out your own form for editing or adding a row |

All of them own an edit session, so you don't need `useEditableTable` or a
`DataEditingProvider`. In edit mode the session holds just the row being
edited (copy option `Selected`); in create mode it starts empty (`Empty`). Save
applies the change to the source table.

## TableWithEditForm

```tsx
<TableWithEditForm
  config={config}
  createFields={createFields}
  createTitle="New instrument"
  dataSource={dataSource}
  fields={fields}
  formTitle={(row) => `Instrument ${row.ric}`}
  validate={validateInstrument}
/>
```

The form is shown in a Salt `SidePanel` to the right of the table. Selecting a
row shows it read-only; Edit makes the form editable and New replaces it with
a create form. While a form is being edited, row selection is locked and the
panel can't be closed.

| Prop | Description |
| ---- | ----------- |
| `panelVisibility` | `"on-select"` (default): the panel opens when a row is selected, or Edit or New is clicked, and closes when the selection is cleared or its close button is clicked. `"always"`: the panel is always shown, with the `placeholder` text when no row is selected, and has no close button. |
| `panelClassName` | Class for the `SidePanel`, e.g. to set `--saltSidePanel-width` (default `320px`). Any CSS length works, including a percentage such as `min(460px, 45%)`; the form keeps its width while the panel slides open. |
| `fields` | Fields shown for the selected row. See [Fields](#fields). |
| `createFields` | Fields shown when adding a row. Defaults to `fields`. |
| `allowCreate` | Show the New button. Default `true`. |
| `validate`, `validateCreate` | Client-side validation for edit and create. `validateCreate` defaults to `validate`. |
| `formTitle` | Panel title for the selected row: a string, or a function of the row. |
| `createTitle` | Panel title for the create form. Default `"New"`. |
| `placeholder` | Text shown in the panel when no row is selected. |
| `confirmCancel` | Asked before discarding unsaved changes. See `useConfirmDiscard`. |
| `onModeChange` | Called with `"view"`, `"edit"` or `"create"`. |
| `onSaved`, `onCancelled` | Called after an edit or a new row is saved, or discarded. |
| `deleteMode`, `editSessionApi`, `rowDefaults`, `onError` | Passed to the form's edit session. |
| `className`, `style` | For the container. |
| `testId` | Suffix for `data-testid`s. |

Other `Table` props are passed through. For anything beyond these, such as
extra toolbar content, compose the layout yourself.

## Composing your own layout

`TableWithEditForm` covers a table with a generated form. When you need your
own header, toolbar, panel layout or form content, such as tabs or custom
editors, give `TableWithEditForm` `children`. It always renders its container,
a flex row, and owns the editing state: mode, selected row, side panel and edit
session. Without `children` it lays out a default toolbar, table and panel;
with `children` you lay out the pieces it is built from, and it takes only the
editing props (`dataSource`, `confirmCancel`, `panelVisibility`, `rowDefaults`,
`onModeChange`, ...) and `className`/`style`. The pieces, all in
`@vuu-ui/vuu-table-extras`:

| Component | Role |
| --------- | ---- |
| `TableWithEditFormTablePanel` | A column holding the table and anything above or below it, such as a header or toolbar. Fills the space beside the side panel. |
| `TableWithEditFormTable` | The table, sized to fill the rest of `TableWithEditFormTablePanel`. Selecting a row selects it for the form; selection is locked while editing. Takes `Table` props. |
| `TableWithEditFormPanel` | The Salt `SidePanel` for the form, on the right. Opens and closes with the selection. Takes `SidePanel` props, such as `className` and `style`; set its width with `--saltSidePanel-width` (any CSS length). Compose `TableWithEditFormPanelHeader` and `SidePanelContent` inside it. |
| `TableWithEditFormPanelHeader` | The panel's `SidePanelHeader`. Its first child fills the width and a close button follows; pass `canClose={false}` to leave the close button out. Takes `SidePanelHeader` props. |
| `TableEditorForm` | The form for the selected row. Renders `children`, or an `EditField` per entry in `fields`. Renders nothing when no row is selected. Takes `EditForm` props such as `validate` and `title`. Renders its own Save and Cancel only without `children`; with `children`, place `TableEditorButtons` yourself. |
| `TableEditorCreateForm` | The form for a new row, shown in create mode. Takes `CreateRowForm` props. Renders `children` after any `fields`; see [Custom create forms](#custom-create-forms). |
| `TableEditorPlaceholder` | Its `children`, shown only when no row is selected and no row is being created. |
| `TableEditorToolbar` | A row for controls above the table. |
| `TableEditorEditButton` | Makes the selected row's form editable. |
| `TableEditorNewButton` | Enters create mode. |
| `TableEditorModeToggle` | View/Edit toggle. |
| `TableEditorButtons` | Save and Cancel. Render inside a composed `TableEditorForm`, or a `TableEditorCreateForm` with `showButtons={false}`. |
| `TableEditorPanelCloseButton` | Closes the side panel; not rendered while the panel can't be closed. `TableWithEditFormPanelHeader` includes one; use this to place it yourself. |

`TableWithEditForm` provides the Salt `SidePanelProvider`, so `TableWithEditFormPanel`
(or any Salt `SidePanel` inside it) opens and closes with the selection. Any
component inside it can call `useTableEditor()` for the state and
actions: `mode`, `isEditing`, `selectedRow`, `panelOpen`, `canClosePanel`,
`startEdit()`, `startCreate()`, `cancel()` and `setPanelOpen()`.

```tsx
import {
  TableWithEditFormPanel,
  TableWithEditFormPanelHeader,
  TableEditorButtons,
  TableEditorCreateForm,
  TableEditorForm,
  TableEditorModeToggle,
  TableEditorNewButton,
  TableEditorPlaceholder,
  TableEditorToolbar,
  TableWithEditFormTablePanel,
  TableWithEditForm,
  TableWithEditFormTable,
  useTableEditor,
} from "@vuu-ui/vuu-table-extras";

const PanelHeader = () => {
  const { mode, selectedRow } = useTableEditor();
  return (
    <TableWithEditFormPanelHeader>
      <SidePanelTitle>
        {mode === "create" ? "New instrument" : selectedRow?.description}
      </SidePanelTitle>
    </TableWithEditFormPanelHeader>
  );
};

const InstrumentEditor = ({ dataSource }) => (
  <TableWithEditForm dataSource={dataSource} style={{ height: 500 }}>
    <TableWithEditFormTablePanel>
      <TableEditorToolbar>
        <H2>Instruments</H2>
        <TableEditorNewButton>New instrument</TableEditorNewButton>
      </TableEditorToolbar>
      <TableWithEditFormTable config={config} />
    </TableWithEditFormTablePanel>
    <TableWithEditFormPanel>
      <PanelHeader />
      <SidePanelContent>
        <TableEditorPlaceholder>Select an instrument</TableEditorPlaceholder>
        <TableEditorForm validate={validateInstrument}>
          <TableEditorModeToggle />
          <Tabs defaultValue="details">
            {/* TabBar ... */}
            <TabPanel value="details">
              <EditField label="Description" name="description" />
            </TabPanel>
            <TabPanel value="trading">
              <EditField label="Lot size" name="lotSize" serverDataType="int" />
            </TabPanel>
          </Tabs>
          <TableEditorButtons />
        </TableEditorForm>
        <TableEditorCreateForm fields={createFields} validate={validateInstrument} />
      </SidePanelContent>
    </TableWithEditFormPanel>
  </TableWithEditForm>
);
```

- `EditField`s inside `TableEditorForm` edit the selected row; they don't need
  a `dataRow`. They are read-only until the form is in edit mode.
- A custom editor, such as a picker that edits a non-field value, should use
  `useCustomEditField`. It commits to the form's edit session, so its changes
  are saved, or discarded, with the fields, and it resets itself when editing
  ends. There's no need to track or reset the value yourself.
- After a save, `selectedRow` holds the saved values, so headers built from it
  update immediately.
- `TableEditorForm` and `TableEditorCreateForm` take `onSaved` and
  `onCancelled`, for side effects such as a notification. They run before the
  panel is updated, so there's no need to close or reset anything yourself.

See the showcase examples `EditForms / TableWithForm`,
`TableWithFormAlwaysVisible` and `TableWithCustomForm`, and the user-admin
`UsersPage`, `GroupsPage` and `RolesPage`. `UsersPage` keeps its own page
layout and a form with tabs and a module permissions picker; `GroupsPage` and
`RolesPage` also have custom create forms. `RolesPage` picks a different form
for each row, using `useEditFormContext().dataRow` inside `TableEditorForm`.

### Custom create forms

When a new row's values aren't one input per column, leave out `fields` and
render your own editors as `children`. Stage each value with `setValue` from
`useEditFormContext()`; staged values are what `validate` receives and what is
added when the user clicks Create.

```tsx
const NewGroupValues = ({ groupName, roleAssignments }) => {
  const { fieldErrors, setValue } = useEditFormContext();
  useEffect(() => setValue("group_name", groupName), [groupName, setValue]);
  useEffect(
    () => setValue("role_assignments", roleAssignments),
    [roleAssignments, setValue],
  );
  return fieldErrors.group_name ? (
    <p role="alert">{fieldErrors.group_name}</p>
  ) : null;
};

const CreateGroupForm = () => {
  const [suffix, setSuffix] = useState("");
  // ... other local state
  return (
    <TableEditorCreateForm onSaved={notifyCreated} validate={validate}>
      <Input value={suffix} onChange={(e) => setSuffix(e.target.value)} />
      <NewGroupValues groupName={groupName} roleAssignments={roleAssignments} />
    </TableEditorCreateForm>
  );
};
```

- `setValue(name, value)` also clears a validation error keyed by `name`, so
  keying errors to the value they describe clears them as the user edits.
  `EditField`s in a create form go through `setValue` too.
- If the row is added but the save then fails, the error is shown and Create
  stays enabled. Clicking it again retries the save without adding the row a
  second time.
- Local state in the create form survives between creates unless it remounts.
  Render it only while `useTableEditor().mode === "create"` to start each new
  row from a blank form.

## Fields

`fields` and `createFields` are lists of `CreateRowFormField`, the props of an
`EditField` without `dataRow`:

```ts
const fields: CreateRowFormField[] = [
  { label: "RIC", name: "ric", readOnly: true },
  { label: "Description", name: "description" },
  { label: "Lot size", name: "lotSize", serverDataType: "int" },
  { label: "Active", name: "active", type: "checkbox" },
  {
    label: "Exchange",
    name: "exchange",
    optionMap: { label: "description", value: "code" },
    table: { module: "SIMUL", table: "exchanges" },
    type: "dropdown",
  },
];
```

- `serverDataType` converts the typed text before it is sent (default
  `"string"`, or `"boolean"` for checkboxes).
- `required` defaults to `true` in a create form. Set it to `false` for
  optional fields.
- `clientSideEditValidationCheck` validates a single field as the user types.
- A `dropdown` field gets its options from a lookup table. See
  [Lookups](./06-Lookups.mdx).

## CreateRowForm

```tsx
<CreateRowForm
  dataSource={dataSource}
  fields={createFields}
  key={formKey}
  onCancelled={close}
  onSaved={close}
  title="New instrument"
  validate={validateInstrument}
/>
```

The row is added only when the user clicks Create and every check passes:
required fields, `validate`, and the server. If the server rejects the row,
its message is shown above the fields and the user can correct the values and
try again.

A `CreateRowForm` adds one row. To add another, close it from `onSaved`, or
change its `key` to get a fresh form.

## EditForm

Use `EditForm` when you want to lay out the fields yourself.

```tsx
import { EditField, EditForm } from "@vuu-ui/vuu-data-editing";

<EditForm
  dataRow={row}
  dataSource={dataSource}
  isEditMode={isEditMode}
  key={row.key}
  onCancelled={() => setIsEditMode(false)}
  onSaved={() => setIsEditMode(false)}
  title={`Instrument ${row.ric}`}
  validate={validateInstrument}
>
  <EditField dataRow={row} label="Description" name="description" />
  <EditField dataRow={row} label="Lot size" name="lotSize" serverDataType="int" />
</EditForm>;
```

- In edit mode, the row must be the one selected in `dataSource`. Fields are
  read-only until `isEditMode` is true (or, if omitted, until the nearest
  `EditModeProvider` is in edit mode).
- For create mode, pass `mode="create"`, `columns` and `requiredColumns`, and
  give each field `dataRow={{ key: EditSession.newRowKey }}` and `deferNewRow`.
  `CreateRowForm` does all this for you.
- A component inside the form can call `useEditFormContext()` for the form
  state, for example to show fields depending on other values:

  ```tsx
  const ExpiryField = ({ row }) => {
    const { getValues } = useEditFormContext();
    return getValues().type === "future" ? (
      <EditField dataRow={row} label="Expiry" name="expiry" />
    ) : null;
  };

  <EditForm {...props}>
    <EditField dataRow={row} label="Type" name="type" />
    <ExpiryField row={row} />
  </EditForm>;
  ```

- `showButtons={false}` hides the built-in Save and Cancel so you can render
  your own. A component inside the form can call `useEditFormContext()` to get
  `submit()`, `cancel()`, `canSave` and the rest of the form state. If the
  buttons must live outside the form, such as in a dialog footer, use
  `useEditForm` instead (see below).
- `saveLabel` defaults to "Save", or "Create" in create mode.

## Validation

`validate(values)` returns an object of error messages keyed by field name.
It runs on submit, with `values` being the row's current values including
unsaved edits. Errors are shown on the fields, and nothing is saved until the
object is empty.

```ts
const validateInstrument: EditFormValidator = ({ currency, lotSize }) => {
  const errors: Record<string, string> = {};
  if (!["EUR", "GBP", "USD"].includes(currency as string)) {
    errors.currency = "Unknown currency";
  }
  if (typeof lotSize === "number" && lotSize <= 0) {
    errors.lotSize = "Lot size must be greater than zero";
  }
  return errors;
};
```

Validation happens in three places:

1. `clientSideEditValidationCheck` on a field: as the user types.
2. `validate` on the form: when the user clicks Save or Create.
3. The server: when the edit or row is sent. Rejections are shown in the
   form's error banner. See [Error handling](./09-ErrorHandling.mdx).

## Custom fields

`EditField` handles text, checkbox and dropdown values. For anything else,
such as a list of tags or a value edited with several controls, write your own
field with `useCustomEditField`. It records the value in the form's edit
session, so the form knows it is dirty and Save sends it.

```tsx
const TagsField = ({ dataRow, name }) => {
  const originalValue = useMemo(() => parseTags(dataRow[name]), [dataRow, name]);
  const { error, isDirty, setValue, value = originalValue } =
    useCustomEditField<string[]>({
      equals: sameTags,
      name,
      originalValue,
      rowKey: dataRow.key,
      serialize: (tags) => tags.join(","),
    });
  // render value, call setValue(nextTags) when it changes
};
```

- `serialize` turns your value into the scalar sent to the server.
- `equals` decides when the value is back to the original, so the edit is
  dropped and the form is clean again.
- The hook returns `{ value, setValue, reset, isDirty, committing, error }`.
- It uses the edit session from the enclosing form. Pass `editSession` to use
  another.

:::caution
Pressing Enter in a single text input inside a `<form>` submits it. If your
field uses Enter for something else, call `event.preventDefault()`.
:::

## Building your own form

`EditForm` is built on `useEditForm`, which you can use directly. It takes the
same props and returns the form state and actions: `submit(force?)`,
`cancel()`, `setValue(name, value)`, `getValues()`, `fieldErrors`, `saving`,
`error`, `isDirty`, `canSave` and the `editSession`. Wrap your fields in a
`DataEditingProvider` with the returned `editSession`.

## Things to know

- Table rows passed to `onSelect` are proxies that are only valid during that
  render. To keep one, copy it with `getDataRowValues(row)`.
- `rowDefaults` must be a stable reference. A new object recreates the edit
  session.
